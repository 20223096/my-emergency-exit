# 최종 시연 진행 순서

## 사전 준비

1. 백엔드를 `http://127.0.0.1:8000`에서 실행한다.
2. 프론트엔드를 `http://localhost:5173`에서 실행한다.
3. 브라우저 확대율을 100%로 설정한다.
4. 지도에서 `서울역 4호선 피난경로 프로토타입`을 선택한다.
5. 화면 하단의 “실제 재난 안내가 아닌 실험용 프로토타입” 고지를 먼저 설명한다.

## 발표 흐름

### 1. 기본 경로

- S3를 선택한다.
- 시나리오는 `기본 조건`으로 둔다.
- `경로 계산`을 누른다.
- `현재 조건 계산 결과`가 11번 출구, 56m, 57.5초인지 확인한다.
- 단일 계산은 차단 전/후 비교 카드가 아니라는 점을 설명한다.

### 2. 화재 A

- `화재 A · 11번 접근 통로 차단`을 선택한다.
- `기본 경로와 비교`를 누른다.
- 차단 전 11번/56m/57.5초와 차단 후 12번/60m/60.833초를 확인한다.
- 화재 위치는 사고 이력이 아니라 가정임을 설명한다.

### 3. 화재 B

- `화재 B · 승강장 주 계단 차단`을 선택한다.
- 비교를 실행한다.
- 차단 후 13번/66m/66.667초와 가정 대체 계단 B 경로를 확인한다.
- 대체 계단의 실제 존재가 확인된 것은 아니라고 설명한다.

### 4. 화재 B + 혼잡

- 화재 B를 유지한다.
- 혼잡 구간 `STAIR_B`, 지연 `20`을 선택하고 `혼잡 지연 추가`를 누른다.
- 비교를 다시 실행한다.
- 출구와 거리는 13번/66m로 같고 시간이 86.667초로 증가했는지 확인한다.

### 5. 대피 경로 없음

- `대피 경로 없음 테스트 · 계단 A+B 차단`을 선택한다.
- S3가 자동 선택되는지 확인한다.
- 비교를 실행한다.
- 기본 경로는 보이지만 변경 경로는 그려지지 않고 `이동 가능한 경로 없음`이 표시되는지 확인한다.
- 거리와 시간은 0이 아니라 `null` 의미의 대시로 표시됨을 설명한다.

### 6. 상태 초기화

- `초기화`를 누른다.
- 시나리오·혼잡·결과가 비워지는지 확인한다.
- 다시 기본 경로를 계산해 11번/56m/57.5초가 복원되는지 확인한다.

### 7. 새로고침

- 브라우저를 새로고침한다.
- 이전 시나리오·혼잡·결과가 남지 않고 기본 컨트롤로 돌아오는지 확인한다.

## 촬영해야 할 증거 화면

이 환경에서는 자동 스크린샷을 만들 수 없으므로 다음 화면을 수동 촬영한다.

1. 서울역 지도 + S3 기본 경로
2. 화재 A의 차단 전/후 카드와 두 경로
3. 화재 B의 계단 A 차단 및 대체 계단 B 경로
4. 화재 B + `STAIR_B +20s` 결과
5. 계단 A+B 차단의 `이동 가능한 경로 없음`
6. 초기화 직후 결과가 비워진 화면
7. 새로고침 직후 기본 컨트롤 화면

각 캡처에는 지도 선택, 출발점, 시나리오 드롭다운과 결과 카드가 함께 보이게 한다. 가능하면 1440×900 또는 1280×800에서 촬영하고, 브라우저 주소나 개인 정보는 제외한다.
