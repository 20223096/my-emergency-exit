# 다중 인원 대피 혼잡 실험 모델 가정

구현 기준: `seoul-station-line4-prototype-v1`  
모델: `deterministic-fixed-route-fifo-capacity-experiment@0.1.0`

> 이 모델은 사용자가 정한 처리용량과 고정 경로 정책을 시험하는 MVP다. 실제 서울역의 통로 폭·밀도·처리용량·군중 행동을 측정하거나 검증한 피난 시뮬레이션이 아니다.

## 1. 기존 구조 감사

기존 단일 인원 API는 Dijkstra 탐색으로 이동시간이 가장 작은 출구를 선택한다. 평지 간선은 `length_m / walking_speed_mps`, 계단 간선은 `length_m / stair_speed_mps`를 사용하고 사용자 고정 지연을 더한다. 모든 현재 간선은 양방향이다. 차단 간선은 인접 그래프에서 제외하고 폐쇄 출구는 출구 후보와 연결에서 제외한다.

- 출발점: `S1`, `S2`, `S3`
- 출구 후보: `EXIT_10`~`EXIT_14`; 공식 비상구 인증 상태는 미확인
- 계단: `STAIR_A` 14m, `STAIR_B` 16m
- 평지 통로: 19개
- 통로 폭, 면적, 실제 밀도, 실제 초당 처리량: 데이터에 없음

| 간선 | 연결 | 종류 | 가정 길이 | 방향 |
|---|---|---|---:|---|
| L4P01 | S3–P_SOUTH | 평지 | 8m | 양방향 |
| L4P02 | P_SOUTH–STAIR_A_LOWER | 평지 | 6m | 양방향 |
| STAIR_A | STAIR_A_LOWER–STAIR_A_UPPER | 계단 | 14m | 양방향 |
| L4P03 | P_SOUTH–STAIR_B_LOWER | 평지 | 12m | 양방향 |
| STAIR_B | STAIR_B_LOWER–STAIR_B_UPPER | 계단 | 16m | 양방향 |
| C01 | STAIR_A_UPPER–C_CENTER | 평지 | 6m | 양방향 |
| C02 | STAIR_B_UPPER–C_WEST | 평지 | 8m | 양방향 |
| C03 | S1–C_EAST | 평지 | 12m | 양방향 |
| C04 | S2–C_WEST | 평지 | 15m | 양방향 |
| C05 | C_WEST–C_CENTER | 평지 | 18m | 양방향 |
| C06 | C_CENTER–C_EAST | 평지 | 16m | 양방향 |
| E10_IN / OUT | C_EAST–X10–EXIT_10 | 평지 | 8m / 10m | 양방향 |
| E11_IN / OUT | C_CENTER–X11–EXIT_11 | 평지 | 10m / 12m | 양방향 |

| E13_IN / OUT | C_WEST–X13–EXIT_13 | 평지 | 12m / 10m | 양방향 |
| E14_IN / OUT | C_WEST–X14–EXIT_14 | 평지 | 18m / 10m | 양방향 |

길이는 모두 기존 그래프의 실험용 가정값이며 SVG 좌표에서 산출한 값이 아니다. 원본 그래프 JSON은 변경하지 않았다.

## 2. 별도 API

- `POST /api/multi-agent/simulate`: 입력 조건 한 개 실행
- `POST /api/multi-agent/compare`: 같은 인원·속도·용량에서 차단 없는 기준과 요청 조건을 각각 실행

기존 `/api/routes/calculate`, `/api/routes/compare`의 계약과 계산 코드는 유지한다.

주요 입력은 `start_counts`, `start_delays_s`, 평지/계단 속도, 차단 간선·폐쇄 출구, 평지/계단 기본 처리용량, `edge_capacity_overrides_per_s`, 기록 간격, 최대 경과시간이다. 용량 단위는 실험상 `명/초`이며 공식 시설 수치가 아니다.

## 3. 결정적 FIFO 정책

1. 각 출발점은 기존 단일 인원 계산으로 차단 조건을 반영한 최단시간 경로를 한 번 선택한다.
2. 모든 사람은 그 경로를 유지한다. 대기열을 보고 재탐색하거나 경로를 분산하지 않는다.
3. 출발 지연 이후 사람이 첫 간선 대기열에 들어간다.
4. 한 간선의 입장 시각은 이전 입장으로부터 최소 `1 / capacity_per_s`초 뒤다.
5. 같은 물리 간선 ID의 양방향 이동은 하나의 처리용량을 공유한다.
6. 간선 이동시간과 입장 전 대기시간을 분리한다. 한 사람의 다음 간선 준비 시각은 이전 간선 이동 완료 이후이므로 동시에 여러 간선에 존재하지 않는다.
7. 같은 준비 시각은 출발점 ID·사람 번호와 이벤트 생성 순서로 결정적으로 처리한다. 이는 실제 우선순위가 아니라 재현성 정책이다.
8. 사용자 `congestion_delays`는 기존과 같이 간선 이동시간에 더해지는 고정값이며 처리용량 대기와 별도다.

`time_step_s`는 상태 기록 샘플 간격이다. 이동과 입장은 연속 시각으로 계산해 1명 결과가 기존 단일 경로 시간과 일치하도록 했다.

## 4. 결과와 종료 상태

- 도착 인원과 출구별 도착 인원
- 미도달 인원 및 그중 처음부터 경로가 없는 `no_route_people`
- 도착한 사람만 대상으로 한 마지막·평균 도착시간
- 간선별 입장 인원, 최대 대기 인원, 최대 관측 대기시간, 최소 입장 간격
- 기록 시각별 간선 대기 인원
- 최대 대기 인원/시간 순서의 병목 후보

종료 사유는 다음을 구분한다.

- `ALL_REACHABLE_AGENTS_ARRIVED`: 모든 입력 인원 도착
- `COMPLETED_WITH_NO_ROUTE_AGENTS`: 도착 인원과 처음부터 경로가 없는 인원이 함께 존재
- `NO_REACHABLE_ROUTES`: 모든 인원에게 경로가 없음
- `TIMEOUT_WITH_ACTIVE_AGENTS`: 최대 시간에 대기·이동·출발 전 인원이 남음
- `NO_AGENTS`: 입력 인원이 0명

종료 시 보존식은 `초기 인원 = arrived + waiting + in_transit + pending_release + no_route`다. `not_arrived_people`는 뒤 네 상태의 합이며 도착시간 평균에 포함하지 않는다.

## 5. 지도 등급

실험 UI는 조건 결과의 최대 대기 인원을 다음 상대 규칙으로 표시한다.

- 모의 통행 원활: 최대 대기 0명
- 모의 대기 발생: 1명 이상, 집중 기준 미만
- 모의 대기 집중: `max(10명, 전체 인원의 20%)` 이상
- 차단: 요청에서 제외된 간선

이 등급은 발표용 가정 시각화이며 실시간 센서, 실제 밀도 또는 안전 기준이 아니다.

## 6. 구현하지 않은 것

- 사람 간 충돌, 신체 크기, 추월, 역류의 물리 상호작용
- 밀도에 따른 속도 변화와 통로 폭 기반 용량
- 심리, 가족·집단 행동, 경로 재선택, 안내 순응도
- 연기·열·유독가스·가시거리와 시간에 따른 차단 변화
- 계단 B 및 내부 연결의 현장 검증
- 실제 CCTV/센서 연결, 실시간 혼잡 탐지, AI 군중 예측
- 장애인·노약자별 이동 특성과 구조 인력 개입

따라서 결과는 입력 가정 사이의 민감도 비교에만 사용한다.
