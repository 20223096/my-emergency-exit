# 서울역 4호선 프로토타입 범위

## 목적과 대상 구역

지도 ID는 `seoul-station-line4-prototype-v1`이다. 4호선 대합실 일부, 1호선에서 4호선으로 이어지는 환승 연결 구간, 회현 방향 승강장 주변을 경로 비교가 가능하도록 축약했다. 이 데이터는 실제 재난 안내나 피난 안전성 인증에 사용할 수 없다.

현재 저장소에는 기획팀 원본 이미지/PDF가 포함되어 있지 않다. 공개 역사 안내자료에서 서울역 출구 번호와 1·4호선 환승 구역의 존재만 참고했다. 내부 통로 연결, 계단 위치, 방향, 길이는 확인하지 못했으므로 모두 단순화 또는 시뮬레이션 가정이다.

## 출발점과 출구

| ID | 구역 | 분류 |
|---|---|---|
| S1 | 대합실, 10번 출구 통로 안쪽 | 기획 범위의 위치를 단순화 |
| S2 | 1호선→4호선 환승 연결 구간 | 기획 범위의 위치를 단순화 |
| S3 | 4호선 승강장, 회현 방향 대합실 계단 주변 | 기획 범위의 위치를 단순화 |

출구 후보는 `EXIT_10`~`EXIT_14`이며 모두 일반 출입구 후보로 경로 계산에 활성화했다. 이는 출구 번호가 역사 안내자료에 존재한다는 의미일 뿐, `official_evacuation_exit`는 모두 `null`이다. 공식 화재 피난 출구로 확인하거나 안전성을 인증하지 않았다. 원본 안내도 확보 시 `active_for_routing`과 내부 접근 간선을 재검증해야 한다.

## 그래프와 근거

- 전체: 21개 노드, 21개 간선
- 직접 확인된 공간 식별자: 출구 번호 노드 5개
- 실제 도면으로 연결까지 확정한 간선: 0개
- `SIMPLIFIED`: 기획 범위의 S1/S2/S3 구역을 축약한 노드·간선
- `SIMULATION_ASSUMPTION`: 대합실 갈림길, 두 계단, 출구 접근 연결
- `UNVERIFIED`: 현재 사용하지 않음. 연결 여부가 불명확한 요소를 활성 간선으로 넣지 않는 용도

각 노드는 `provenance`와 `source_ref`, 각 간선은 `provenance`, `source_ref`, `length_source`, `physical_control_group`을 보존한다. 모든 `length_m`는 `실험용 가정값`이며 SVG 좌표에서 환산하지 않았다. 평행 간선은 없고 한 물리 통제 단위마다 하나의 간선 ID/통제 그룹을 사용한다.

## 층별 구조

- `-1`: 대합실, 환승 연결부, 출구 접근부, 10~14번 출구 후보
- `-2`: 4호선 승강장 S3, 승강장 통로, 계단 하부
- `STAIR_A`, `STAIR_B`만 층간 이동한다. 계단 B는 실제 존재가 확인된 대체 계단이 아니라 시뮬레이션 가정이다.

## 시나리오

- A 접근 차단: `E11_OUT`만 차단한다. `EXIT_11` 자체는 폐쇄하지 않는다.
- A 출구 폐쇄: `EXIT_11`을 후보 및 경유에서 제외한다. 접근 통로 차단과 별개다.
- B 계단 차단: `STAIR_A`를 차단하고 가정 계단 B를 통한 우회를 확인한다.
- B 전체 차단: `STAIR_A`, `STAIR_B`를 함께 차단해 S3의 unreachable/null 처리를 검증한다.

화재 위치는 모두 실제 사고 이력이 아닌 시뮬레이션 가정이다. 정밀 군중 흐름과 연기 확산은 모델링하지 않는다.

## 데이터 한계와 후속 검증

공식 역사 평면도, 현장 실측, 소방 피난계획 자료가 제공되기 전에는 내부 연결과 거리, 통행 방향, 대체 계단 존재, 공식 피난 출구를 확정할 수 없다. 자료 수신 후에도 현재 ID를 무조건 재사용하지 말고 물리 통제 단위를 먼저 확인해야 한다. 기존 `virtual-station-v1`의 A12/A17은 평행 간선 경고 대상으로 보존했으며 신규 지도에서는 해당 문제를 만들지 않았다.
