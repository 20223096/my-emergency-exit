# 서울역 시나리오 테스트 결과

## 공통 조건

평지 1.2m/s, 계단 0.8m/s, 반응시간 5초를 사용했다. 시간은 `거리/해당 구간 속도 + 혼잡 지연 + 반응시간`이다. 아래 수치는 실험용 가정 거리 기반이며 실제 대피시간이 아니다.

## 출발점별 결과

| 시작 | 기본 (출구 / 거리 / 총시간) | 화재 A: E11_OUT 차단 | 화재 B: STAIR_A 차단 |
|---|---|---|---|
| S1 | EXIT_10 / 30m / 30.000s | 동일, 변화 없음 | 동일, 변화 없음 |
| S2 | EXIT_13 / 37m / 35.833s | 동일, 변화 없음 | 동일, 변화 없음 |
| S3 | EXIT_11 / 56m / 57.500s | EXIT_12 / 60m / 60.833s | EXIT_13 / 66m / 66.667s |

S3의 A 우회 증가는 4m/3.333초, B 우회 증가는 10m/9.167초다. A에서 `E11_OUT`만 막는 경우와 `EXIT_11`을 폐쇄하는 경우를 서로 다른 조건으로 검증했으며, 현재 단순 그래프에서는 둘 다 S3가 EXIT_12로 바뀐다. 이것은 다른 11번 접근로가 실제로 없다는 주장이 아니라 현재 프로토타입에 검증된 다른 접근로를 추가하지 않았기 때문이다.

B의 대체 계단은 `STAIR_B`이나 실제 구조에서 존재한다고 확인된 계단이 아니다. 따라서 결과는 알고리즘 우회 동작의 검증값이다.

## 혼잡·경로 없음·초기화

- B 차단 상태에서 `STAIR_B`에 20초 혼잡 지연을 더하면 S3 총시간은 86.667초, 기본 대비 +29.167초다.
- S3에서 `STAIR_A`와 `STAIR_B`를 모두 차단하면 `reachable=false`, 출구·거리·이동시간·총시간은 모두 `null`이다. 0으로 표시하지 않는다.
- 조건을 비운 뒤 다시 계산하면 S3의 기본 EXIT_11 / 56m / 57.500초가 복원된다.
- 계단 속도를 0.5m/s로 낮추면 기본 경로의 시간이 증가함을 확인했다.

## 무결성 및 회귀 검증

- 노드/간선 ID와 참조 무결성 통과
- 층간 간선은 모두 `STAIR`, 평지 간선은 같은 층임을 확인
- 신규 지도 평행 간선 0건, 모든 간선에 물리 통제 그룹 존재
- 모든 신규 간선 거리 출처가 `실험용 가정값`임을 확인
- 기존 `virtual-station-v1` 기본 경로와 A12/A17 품질 경고 테스트 유지
- 기존 요청에서 `stair_speed_mps`를 생략해도 기존 평지 속도로 계산되어 호환됨
