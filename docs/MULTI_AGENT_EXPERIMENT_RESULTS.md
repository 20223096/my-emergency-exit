# 다중 인원 MVP 실험 결과

실행일: 2026-10-28  
지도: `seoul-station-line4-prototype-v1`  
재현 명령: `cd backend && PYTHONPATH=. python3 scripts/multi_agent_matrix.py`

> 아래 수치는 평지 1.2m/s, 계단 0.8m/s, 평지 용량 2명/초, 계단 용량 1명/초를 기본으로 한 **가정 기반 계산 결과**다. 실제 서울역 군중 대피시간·처리용량·병목을 검증한 결과가 아니다.

## 1. 인원 변화 — S3 기본 경로

| 입력 | 출구/도착 | 마지막 도착 | 도착 평균 | 주요 모의 대기 후보 |
|---:|---|---:|---:|---|
| 1명 | 11번 / 1명 | 52.5초 | 52.5초 | 없음 |
| 20명 | 11번 / 20명 | 71.5초 | 62.0초 | L4P01 19명·9.5초, STAIR_A 10명·9.5초 |
| 100명 | 11번 / 100명 | 151.5초 | 102.0초 | L4P01 99명·49.5초, STAIR_A 50명·49.5초 |
| 300명 | 11번 / 300명 | 351.5초 | 202.0초 | L4P01 299명·149.5초, STAIR_A 150명·149.5초 |

1명 결과는 기존 단일 인원 S3 기본 결과(11번, 56m, 52.5초)의 출구·시간과 일치한다. 다중 엔진의 거리는 경로 배정에 사용하지만 군중 결과 지표로 중복 출력하지 않는다.

`L4P01` 대기가 큰 이유는 모든 S3 인원을 시각 0에 한꺼번에 같은 첫 간선에 넣고 2명/초로 제한하는 정책 때문이다. 실제 승강장 분포나 통로 폭을 관측한 결론이 아니다.

## 2. 같은 100명에서 계단 용량 가정 변화

| 계단 가정 용량 | 마지막 도착 | 도착 평균 | STAIR_A 최대 대기 |
|---:|---:|---:|---:|
| 0.5명/초 | 250.5초 | 151.5초 | 75명, 148.5초 |
| 1.0명/초 | 151.5초 | 102.0초 | 50명, 49.5초 |
| 2.0명/초 | 102.0초 | 77.25초 | 0명, 0초 |

용량 가정을 높이면 결과가 줄어드는 것은 모델 정의에 따른 민감도다. 어느 용량도 실제 계단 측정값이 아니다. 2명/초에서도 첫 간선 `L4P01`의 가정 용량 때문에 99명·49.5초의 초기 대기가 남는다.

## 3. 화재·차단 조건 — S3 100명

| 조건 | 도착 출구 | 마지막 도착 | 도착 평균 | 계단 후보 |
|---|---|---:|---:|---|
| 차단 없음 | 11번 100명 | 151.5초 | 102.0초 | STAIR_A 50명·49.5초 |
| 화재 A · E11_OUT 차단 | 12번 100명 | 154.833초 | 105.333초 | STAIR_A 50명·49.5초 |
| 화재 B · STAIR_A 차단 | 13번 100명 | 160.667초 | 111.167초 | STAIR_B 50명·49.5초 |
| 계단 A+B 차단 | 도착 0명 | - | - | 경로 없음 100명 |

화재 A/B의 출구와 1인 이동시간 차이는 기존 경로 엔진을 사용한 고정 경로 배정에서 비롯된다. 다중 모델이 화재나 군중을 감지한 결과가 아니다.

## 4. 일부 미도달과 timeout 구분

### 일부는 도착, 일부는 처음부터 경로 없음

입력 `S1 20명 + S3 20명`, 계단 A+B 차단:

- 20명은 EXIT_10 도착
- S3 20명은 `no_route`
- 마지막 도착 34.5초, 도착한 20명의 평균 29.75초
- 종료: `COMPLETED_WITH_NO_ROUTE_AGENTS`
- 평균에 미도달 20명을 포함하지 않음

### 경로는 있지만 제한시간에 미완료

입력 `S3 300명`, 기본 경로, 최대 60초:

- 도착 8명, 미도달 292명
- 미도달 구성: 대기 227명, 이동 중 65명, `no_route` 0명
- 도착한 8명의 평균 56.0초, 마지막 도착 59.5초
- 종료: `TIMEOUT_WITH_ACTIVE_AGENTS`

두 사례는 각각 경로 연결성 실패와 시간 제한 종료이므로 UI/API에서 별도 상태로 유지한다.

## 5. 검증 결과

- 인원 보존: 자동 테스트 및 각 결과의 `end_state_counts`로 확인
- 간선 처리용량: 연속 입장 간격이 `1/capacity`보다 작지 않음을 테스트
- 차단 간선: 결과의 입장 간선에서 제외됨을 테스트
- 결정성: 동일 입력 결과 객체가 동일함을 테스트
- 경로 없음과 timeout: 서로 다른 종료 사유와 상태로 테스트
- 단일 인원 회귀: S3 52.5초 및 EXIT_11 일치

## 6. 해석 제한

병목 후보는 “현재 입력의 FIFO 대기열이 큰 간선”일 뿐 실제 위험·혼잡 지점이 아니다. 고정 경로라서 다른 출구가 비어 있어도 대기 중 재탐색하지 않으며, 동시에 출발시키는 초기 조건이 첫 간선 대기를 크게 만든다. 실제 적용 전에는 통로 폭, 유효 용량, 출발 분포, 실제 계단 연결과 현장 통과시간을 확보하고 별도 검증해야 한다.
